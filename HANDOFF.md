# Beamwright: project handoff

Hand this file and the repo zip (`beamwright.zip`) to the next assistant. It covers what the game is, how the code is put together, what the owner likes and dislikes, and what's left to do.

## The project

**Beamwright** is a browser puzzle game by **Jalapeño Seed Productions** (GitHub: `jalapenoseed`). You mount optical parts on an optical breadboard and steer ray-traced light into every photocell. It started from a YouTube Short that sent light rays through a parade of optical elements. The comment that kicked it off was "turn light engineering and management into a game and use these sound effects".

- It's plain HTML, CSS and JavaScript with no framework and no runtime dependencies. Node 18+ is only needed for the tools.
- `npm run build` bundles `src/` into one self-contained file, `dist/index.html`.
- It's headed for **itch.io** (HTML5 upload) and **GitHub Pages**. The repo lives at `jalapenoseed/beamwright`.

## What's in the game

- **22 campaign benches** in two chapters.
  - Chapter I, *The Bench*: mirror, beam splitter, concave and convex mirrors, convex and concave lenses, glass block, prism.
  - Chapter II, *Exotic Optics*: critical-angle block (TIR), cat's eye, fiber and fiber bend, water droplet, diamond, hot-air mirage zone.
- **Free bench**, a sandbox with every part unlimited.
- **Bench maker** (the level editor):
  - Place sources, photocells and walls, plus fixed parts of all 14 kinds.
  - An inspector to turn, recolour, size or remove things, and settings for size and the player's parts.
  - **check** runs the solver in a Web Worker and sets par plus the hint solution.
  - Test play, "My benches" saved in localStorage, `BW1-…` share codes, and **submit** to the community.
- **Community benches.** Players submit through a GitHub issue form and a workflow checks the code with the solver. A maintainer adds the `accepted` label and the bench is committed to `community/benches/` and redeployed. Benches appear in the picker with the maker's credit and can be remixed.
- **Navigation.** Esc or the menu key opens a pause menu (resume, restart, prev/next, choose bench, maker, main menu). Every menu works from the keyboard, and the picker moves with the arrow keys.
- **Intro.** A "switch on the bench" gate (needed for the audio unlock) leads into the Jalapeño Seed Productions ident: a beam hits a seed, a jalapeño traces itself in light, and a sting plays. Then the title screen, with "BEAMWRIGHT" written in light.
- **Music.** A title theme at 112 BPM and a bench-picker track at 84 BPM, both synthesized live.
- **Trailer.** `npm run trailer` films a 38-second 1280×720 trailer from the game using Playwright and ffmpeg. It includes a bench-maker scene and was re-rendered after the emitter, photocell and win-sound changes.

The build order matters. These load as globals, in this order: engine, levels, SOLS, solver, codes, COMMUNITY, REPO, WORKER_SRC, audio, skins, gl. After them, `game.js + maker.js + community.js + boot.js` share one IIFE scope. `window.__bw` exposes hooks for tests and the trailer.

### How things work

- **Light.** Each source fires 5 parallel rays (100 lm per beam). Segments carry `d0`/`d1` (distance in cells) and `ev`, which is what the ray met: mirror, split, lens, glassIn, tir, target and so on. Target hits also carry `ti`, the index of the cell they hit. Dispersion is exaggerated on purpose.
- **Sound: "the light is the drum machine".** Sources fire a pulse on the downbeat and it travels one cell per 16th note at 112 BPM. Every `ev` is a percussion hit at that step, so the light path *is* the beat, and drawn pulses run in sync. Under that sit the original sounds: glass bells for placing parts, a sustained tone per lit cell, and a low hum.
- **Rendering.** There are two 2D canvases: `#cv` for objects and `#bv` for additive light. The WebGL2 shader composites them over a black-anodized breadboard. DOM elements with `data-plate` (key, pocket, panel, window, led, shade, accent) are drawn *by the shader*; the HTML supplies only text and hit areas. A plain 2D fallback (`.no-gl`) covers devices without WebGL2.
- **Emitters** are laser heads on fork clamps, with a coloured ID band (a spectrum band for white light) and a lens flare on the downbeat. **Photocells** are a silicon die in a knurled can, with filter glass for colour-only cells and an iris for pinholes. A 24-segment LED meter fills as light arrives, the die flashes when a pulse lands, and a ripple runs out when the cell switches on.
- **Level indices** (`S.li`): 0 and up = campaign, -1 = free bench, -2 = maker test play (`S.testLevel`), -3 = maker, -4 = community bench (`S.ci`).
- **Storage** keys start with `beamwright.`: `progress` (campaign index, or `c:<id>` for community benches), `custom` (my benches), `author`, `last`.

## Commands

```sh
npm run build     # dist/index.html
npm run verify    # all campaign + community benches: solution wins, empty bench doesn't, inventory fits
npm test          # verify + build
npm run solve     # regenerate data/solutions.json (npm run solve -- <index> for one)
npm run itch      # build + itch-build/beamwright-html5.zip
npm run community:check -- BW1-…    # is a code publishable?
npm run community:add -- BW1-… --author "Name"
npm run trailer   # needs Playwright + ffmpeg
```

## What the owner likes (keep these)

- **Studio ident first.** Every project opens with the Jalapeño Seed Productions ident.
- **The look.** Dark, tactile lab hardware: anodized metal, amber VFD readouts (`#ffc366`), the B612 / B612 Mono fonts. They explicitly asked to *avoid the classic AI look*. Text must stay readable (not too dim), and the background shouldn't be too dark.
- **The sound.** They want the **original bell sound set** ("that sound everyone likes") plus the **beam-hit drum machine**: each beam should sound like it hits something and then dissipates or continues, like the video.
  - They did **not** like video-style swish/ping replacements.
  - No vocal or "chanting" pads. Light ambience is OK.
  - The win sound was toned down to a short, quiet phrase in the title theme's key (D major, 112 BPM).
- **Interaction.** The "next bench" key after a win is lit amber and interactive. The hint key glows after 15 seconds of no moves.
- **Format.** They like getting a playable build and a repo zip, then short summaries.

## Gotchas

- **Workflow-to-workflow triggers.** Pushes made with `GITHUB_TOKEN` don't trigger other workflows, so the accept job starts the deploy itself with `gh workflow run deploy.yml`.
- **Clipboard in itch's iframe.** itch blocks the Clipboard API inside its iframe. `copyText()` in maker.js falls back to `execCommand('copy')`.
- **Validate before using a code.** Issue bodies and share codes are untrusted. They go in through env vars only, and `BENCH.decode` range-checks every field. Keep it that way.
- **Software WebGL is slow** in headless browsers. Automated tests force the 2D path by making `getContext('webgl2')` return null.
- **Keep campaign benches verified.** After editing a campaign bench, run `npm run solve -- <i>` and then `npm run verify`.
